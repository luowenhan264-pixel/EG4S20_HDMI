## 1. 结论摘要

| 维度 | lab_ex4_tf | lab_ex5_i2s |
|------|------------|-------------|
| 定位 | TF→SDRAM→HDMI **纯视频** BMP 轮播 | 同视频通路 + HDMI **48 kHz 测试音** |
| 顶层 | `top`（`top_tf_hdmi_audio.v`） | 同名顶层，音频通路已接通 |
| HDMI 音频 | **硬连零**（`I_audio_valid/left/right/acr=0`） | PLL→I2S tone→receiver→ACR→HDMI 核 |
| 按键 | key1 下一张 / key2 自动轮播开停（约 1 s） | 同左 |
| BMP | 最多扫 4 张，640×480×24 非压缩 | 同左 |
| 可靠性 | **更强**：PLL POR≈20 ms + 读图 1 s 超时 abort | **较弱**：复位几乎只跟 `audio_pll_lock`；无读图超时 |
| 文档质量 | 设计文档大体正确，但含“例程6/音频节”残留；工程名错挂 ex5 | **代码说明.md 整份错贴成 ex4**；设计文档可用 |

**一句话**：ex4 适合当“视频+按键+双缓冲”参考；ex5 适合当“HDMI 出声”参考；选题一终稿需把两者能力合并到**单一 bit**，并避开扇区盲扫 / 文案错贴 / 复位不一致等坑。

## 2. lab_ex4_tf 架构

### 2.1 顶层

- 文件：`lab_ex4_tf/src/user_source/hdl_source/top_tf_hdmi_audio.v`，模块名 `top`
- 端口：`clk/rst_n/key1/key2`，数码管，HDMI TMDS+DDC，TF SPI
- TD 工程实际文件名：`src/td_project/lab_ex5_i2s_v1.0.al`（**命名错挂到 ex5**；Runs 目录亦为 `lab_ex5_i2s_v1.0_Runs`）
- 设计文档写的是 `HDMI1.4b_Transmitter_v1.0.al`，与磁盘工程名不一致

### 2.2 时钟 / PLL / 复位

| 时钟 | 来源 | 频率（IP 注释） | 用途 |
|------|------|-----------------|------|
| `clk` | 板载 | 50 MHz | 输入、数码管扫描 |
| `sd_card_clk` | `sys_pll` C0 | 100 MHz | SD/BMP 控制 |
| `ext_mem_clk` / `_sft` | `sys_pll` C1/C2 | 125 MHz / 180° | SDRAM |
| `video_clk` | `video_pll` C0 | 25 MHz | 640×480 像素 |
| `hdmi_5x_clk` | `video_pll` C1 | 125 MHz | TMDS 串行 |

复位：`sys_pll_lock && video_pll_lock` 后计数约 **1_000_000 @50 MHz ≈ 20 ms** 再释放 `rst_all`；释放后忽略后续 PLL 抖锁，避免运行中误复位。  
**无** `PLL_HDMI_AUDIO`。

约束：`timing.sdc` 对 `sd_card_clk/ext_mem_clk/video_clk/hdmi_5x_clk` 做 rename；**无** `audio_mclk` 约束（与纯视频一致）。

### 2.3 按键

- `key1` → `sd_card_bmp.key_next`：手动下一张（忙时只记 1 次 pending）
- `key2` → `key_auto`：`auto_play_en` 翻转；需已扫到 **≥2** 张图才有效
- 消抖：`key_press_debounce`，50 ms（例化参数），默认松开=1 / 按下=0
- 自动周期：`auto_tick = (auto_cnt == CLK_FREQ_HZ-1)` → 在 100 MHz 下约 **1 Hz**；非独立 `PERIOD_MS` 参数，但可改比较常量/参数实现“可配”
- 引脚（`pin.adc`）：key1=`B2`，key2=`C1`，rst_n=`A2`，带 **PULLUP**

### 2.4 TF → SDRAM → HDMI 数据通路

```
TF(SPI) → sd_card_top → bmp_read（扇区盲扫/加载）
       → sd_card_bmp（最多 4 张扇区表 + 双缓冲调度）
       → frame_read_write（写 FIFO，WRITE_V_FLIP=1 抵消 BMP 底向上）
       → sdram（BUF0@0 / BUF1@307200 像素）
       → 读 FIFO → video_timing_data → video_delay
       → RGB（首图前强制黑屏）→ video_rgb_to_axis_640x480
       → hdmi_1_4b_transmitter_core_wrapper（VIC=1, RGB, 48K 配置但音频输入为 0）
       → hdmi_phy_wrapper → HDMI TMDS
```

要点：

- 扫描参数：`SCAN_START_SECTOR=0`，`SCAN_MAX_SECTOR=131071`，`SCAN_TARGET_COUNT=4`
- BMP 合法判定：`BM` + 宽高匹配 + 24 bit + compression=0（`bmp_read.v`）
- **非真正 FAT 目录解析**：按物理扇区找 `BM` 头；文档写 FAT32，代码无 BPB/簇链逻辑
- 双缓冲：写完源数据且收到 `write_finish_toggle`（ex4 另有 `write_done_seen` 防脉冲丢失）后切换 `disp_buf_idx`
- **1 s 超时**：`load_timeout_cnt > 100_000_000` 时 `load_abort`，避免坏图卡死
- HDMI 音频口硬连：`I_audio_valid=0`，左右 PCM=0，ACR=0
- 引脚绑定开发板 **HDMI_B**（C3/G5/F1/E1 + DDC P2/R2）

### 2.5 全局定义 / 其它

- `include/global_def.v`：SDRAM 数据/地址位宽、125 MHz 自刷新相关宏
- `video_define.v`：`VIDEO_640_480`
- 示例图：`doc/TF卡图片` 约 5 张、`doc/convert/output_bmp` 4 张；抽检 BMP 头为 640×480×24 非压缩，文件长 921654（=54+640×480×3）

## 3. lab_ex5_i2s 架构

### 3.1 顶层

- 文件：同路径 `top_tf_hdmi_audio.v`，模块名 `top`
- TD 工程：`src/td_project/HDMI1.4b_Transmitter_v1.0.al`（与设计文档一致）
- 视频/TF/按键/双缓冲骨架与 ex4 **同构**，增量在音频与复位策略

### 3.2 时钟 / PLL / 复位

在 ex4 的 `sys_pll` + `video_pll` 之外增加：

| 时钟 | 来源 | 频率（IP 注释） | 用途 |
|------|------|-----------------|------|
| `audio_mclk` | `PLL_HDMI_AUDIO` C2 | **≈12.295 MHz**（标称 12.288） | I2S 测试音发生 |

复位：

```verilog
assign rst_all = ~rst_n | ~audio_pll_lock;
```

- **未**等待 `sys_pll` / `video_pll` lock，也 **无** 20 ms POR
- 音频 PLL 未锁定则整系统保持复位

`timing.sdc` 额外：`rename_clock audio_mclk`，并把 `audio_mclk` 与 video/sd/mem 设为 **asynchronous** 时钟组。

### 3.3 按键 / TF-SDRAM-HDMI 视频通路

- 与 ex4 同：key1/key2、最多 4 张、双缓冲、640×480@60、HDMI_B
- **差异（重要）**：`sd_card_bmp.v` **无** `load_timeout_cnt` / `load_abort`；提交显示仅依赖 `source_done_seen && write_finish_pulse`，**无** `write_done_seen` 闩锁 → “写完成脉冲早于 source_done”时存在卡 busy 风险
- `bmp_read` **无** `load_abort` 端口（ex4 有）
- `pin.adc`：key/rst 的 `PULLTYPE=NONE`（ex4 为 PULLUP）——板级若无外部上拉需注意

### 3.4 音频通路

```
PLL_HDMI_AUDIO(audio_mclk)
  → hdmi_audio_tone_i2s_64fs（内部方波音阶 do…si…，64fs I2S，左右同样本）
  → I2S_receiver（video_clk 域三拍同步 + 解串 → 24-bit PCM + audio_valid）
  → audio_arc_calculate（N=6144，动态 CTS）
  → hdmi_1_4b_transmitter_core_wrapper（与 AXIS 视频合流）
  → PHY → HDMI_B（显示器扬声器）
```

- 顶层 tone 参数：`PHASE_INC`（模块内实际用音阶 LUT）、`AMP=2000000`
- 采样：48 kHz（与 HDMI 核 `AUDIO_SAMPLE_RATE="48K"` 一致）
- 无外部 I2S 引脚占用（`pin.adc` 中 J4 I2S 注释为历史遗留，已注释掉）

### 3.5 文档

- `设计参考例程文档.md`：标题为例程5，音频原理/接口较完整；仍多处写“相对例程 6”
- `代码说明.md`：**与 lab_ex4_tf 的代码说明逐字相同**（标题仍写 lab_ex4、纯视频、工程路径指到 `lab_ex4_tf/.../lab_ex5_i2s_v1.0.al`）——复制粘贴错误已核实

## 5. 对照选题一 MUST 的差距

> MUST 为竞赛终稿要求；下列标注为例程相对 MUST 的参考级差距。

| MUST | 例程现状 | 差距说明 |
|------|----------|----------|
| ≥4 张 640×480 24-bit BMP | 两例均 `SCAN_TARGET_COUNT=4`；示例目录有 ≥4 张合格 BMP | **满足参考能力**；依赖卡内容与扇区布局 |
| SDRAM 缓存 + HDMI 稳定显示 | 双缓冲 + HDMI 1.4b 640×480@60；ex4 POR 更稳 | **基本满足**；ex5 复位/超时偏弱，稳定性参考优先看 ex4 |
| 至少两键：下一张 + 自动轮播开停（周期可配） | key1/key2 齐备；周期≈1 s（绑 `CLK_FREQ_HZ`） | **功能满足**；“周期可配”仅为改参/改常量，无独立 UI/寄存器级配置 |
| HDMI 能出声 | **仅 ex5**；ex4 音频硬零 | **ex4 不满足**；ex5 仅为测试音阶，非内容音频 |
| 最终单一 bit 固化 | `output_bit` 下 **两个** bit | **不满足终稿形态**；两 bit 仅作分阶段参考 |

**合并视角**：终稿若以 MUST 验收，应基于 **ex5 音视频通路 + ex4 复位/超时可靠性** 做成一个工程、一个 bit，而不是现场切换两个 bit。

## 6. 风险与坑

### 6.1 已核实：ex4 音频硬连零

`top_tf_hdmi_audio.v` 中：

- `I_audio_valid = 1'b0`
- `I_audio_left/right_data = 24'd0`
- `I_acr_* = 0`

设计文档 §3.6 仍描述 tone/I2S/ACR，与实现不符——文档残留，易误导“ex4 也能出声”。

### 6.2 已核实：BMP / “FAT” 边界

- 代码是 **物理扇区顺序扫 `BM` 头**，不是 FAT32 目录项/簇链解析；删除文件后扇区残留仍可能被扫到（`sync_to_sd.py` 文档已点明）
- 扫描跨度默认约 64K 扇区（≈32 MiB）；大卡、碎片、非连续写入可能导致漏扫/扫到旧图
- 合法图硬条件：640×480、24-bit、非压缩；行宽 1920 可被 4 整除，无 padding 特例问题
- 文件需大致连续存放，否则 `file_sector_count` 跳扫逻辑与真实 FAT 簇链不一致会出错
- ex5 无读图超时：坏图/截断更容易 **永久 load_busy**

### 6.3 已核实：HDMI_B

- 文档与 `pin.adc` 均指向 HDMI_B 引脚组；插错 HDMI_A 会黑屏/无声——操作硬坑，非逻辑 bug

### 6.4 已核实：md 文案复制粘贴 / 标题错误

| 文件 | 问题 |
|------|------|
| `lab_ex5_i2s/代码说明.md` | 标题与全文仍是 **lab_ex4_tf / 纯视频**，路径全指向 ex4 |
| `lab_ex4_tf/设计参考例程文档.md` | 工程路径写成 `HDMI1.4b_Transmitter_v1.0.al`，实际为 `lab_ex5_i2s_v1.0.al`；§3.6 音频残留 |
| 两例设计文档 | 多处“例程 6”“相对例程 6”编号错位 |
| `lab_ex4_tf` TD 工程名 | 目录是 ex4，工程名是 **lab_ex5_i2s_v1.0**——极易开错工程/交错 bit |

### 6.5 其它风险

- ex5 复位不依赖 video/sys PLL lock：极端上电序下可能更早跑视频域逻辑
- 音频 mclk 为 12.295 MHz 近似值，一般可听，但对严格时钟恢复属近似实现
- 两例 bit 体积相同（629624 B）但 **SHA256 不同**，勿按体积判断是否同一设计
- 自动轮播默认关闭，需 key2；仅 1 张图时 key2 无效（需 ≥2 张）

## 7. 竞赛安全差异化架构建议（只高层面，不写具体改码）

1. **单一交付形态**：一个工程、一个 top、一个 bit，同时满足 BMP 轮播 + HDMI 出声；ex4/ex5 仅作模块参考源。  
2. **可靠性取 ex4、音频取 ex5**：统一 POR（多 PLL lock + 延时）+ 读图超时/abort + write_finish 闩锁，再挂音频链。  
3. **存储访问差异化**：避免“全盘扇区盲扫找 BM”作为唯一方案；可改为受限索引表、固定扇区表、或真正轻量目录解析，降低残留扇区误识别。  
4. **人机与可配**：轮播周期用独立参数/拨码/按键档位表达“可配”，避免与 SD 时钟频率强耦合。  
5. **音频差异化**：测试音可保留自检；正式演示可走 ROM/外部数字音频等更高辨识度通路，但保持 HDMI 包与 ACR 正确。  
6. **工程卫生**：工程名、bit 名、文档标题三者对齐；删掉错误粘贴的“例程6/纯视频说明”，避免评审/自测踩文档坑。  
7. **验收路径固化**：FAT32 卡 + 转换/同步脚本 + 强制 HDMI_B + 带扬声器显示器，写入自测清单。
